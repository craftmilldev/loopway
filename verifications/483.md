# Verification for PR 483: loopway v2 rip-out

This PR only removes code. So the question for each check is whether what's left still works, and whether the removal reached anything it shouldn't have. Everything below ran on 2026-11-04, on a Mac, unless it says otherwise.

**Bottom line:** the code works locally and in CI. Nothing has touched production, Vercel, a real sender or a real release, and those are where the risky parts of this PR land. The PR stays a draft: the replacement read path isn't built.

### The migration

`040_v2` is the one step that can't be undone, so it has its own test in `packages/web/test/migrate-existing-data.test.ts`. The test rolls a database back to just before the migration, fills it with rows, and applies the migration. It uses a user with a personal org, a user with none, a shared org, an inbox, a message, a bot and a `bot_inboxes` row, and it confirms that:

- the username moves from `orgs.slug` to `users.username`, and a user with no personal org gets null
- inboxes and messages are empty afterwards
- only `users`, `login_codes`, `inboxes`, `messages` and `schema_migrations` remain
- an inbox can be inserted under a user, and is deleted along with that user

### Packaging

- `npm pack -w @loopway/cli` makes a tarball with no `@loopway/*` dependencies.
- I gave that tarball the `manifest.txt` the release workflow builds, and ran the real `install.sh` against it with `LOOPWAY_DOWNLOAD_URL=file://...` and a throwaway npm prefix. It installed, `loopway --version` printed `2.0.0`, and `loopway whoami` worked against the local server.
- `.github/workflows/release-cli.yml` still parses as YAML.

### The landing page

- I took screenshots with headless Chrome at 1280px wide (whole page) and in a 390px frame. The layout holds at both, with the terminal figure gone.
- I compared every class name in the client with `styles.css`, and every `var(--x)` with its definition.

### Auth coverage

I first deleted `authz.test.ts` with the rest of the org tests, then restored the parts that still apply while writing this file. It checks that every route not on the public list answers `401` without a token, and that a stranger gets `404` on all six routes that name an inbox, leaving the inbox unchanged.

### A bug these checks found

Cutting the dashboard CSS also removed `--indigo-600` and `--indigo-200`, which the landing page uses, so the Level 3 swatch had no colour. All tests passed with this bug in place. It's fixed in `6356153`, and I confirmed the swatch is back in a new screenshot. `packages/web/test/styles.test.ts` now checks that every custom property is defined, and I confirmed that test fails with one removed.

The smoke test's other surprise was not a bug: a 420px window looked clipped, but that's headless Chrome's minimum window width. The 390px frame wraps correctly.

## What I didn't check

### Couldn't do without acting on production or a live service

- **`040_v2` on production data, or a copy of it.** I have no production access and didn't try to get any. The test uses a handful of rows I wrote, not real ones. Row counts, migration run time and any oddities in old rows are all unknown. Take a Supabase backup before merging, because there's no down migration.
- **A Vercel deployment.** `vercel.json` only deploys `main`, so there's no preview for this branch. The server has only run through `scripts/dev.ts` and the tests, never as a Vercel function. That includes the real build-time migration path over Supabase's session pooler, and the removal of `@vercel/functions`.
- **A real CLI release.** `release-cli.yml` only runs on `main`, so it's parsed but not run. The new version logic (package version 2.0.0 over last release 0.4.7) is unproven.
- **A v1 CLI updating itself to 2.0.0.** I only confirmed the server answers `426`. An installed 0.4.7 fetching the 2.0.0 tarball, and what its `bots run` does at that moment, is untested.
- **Real senders.** GitHub was a webhook I signed by hand. Linear, Vercel, Granola and Resend ran only through the existing adapter tests, not live deliveries.
- **Real login email.** The dev server printed the code to its console, so Resend wasn't used.
- **The production cron.** Locally I only saw it refuse a request with no token. `packages/web/test/sources/schedule.test.ts` covers the rest through the app.

### Could have done, and didn't

- **A code review.** No one has read this diff but me. review-bot skips drafts, and I didn't run `/code-review`.
- **A line-by-line audit of the deleted tests.** This PR deletes 54 test files, and I judged them by file name and by what they imported. Most test code that's gone, but a deleted file could also have covered something that stays. `authz.test.ts` did, and I only caught that by going back to look, so others may too.
- **Other browsers.** The page was only rendered in headless Chrome, not Safari or Firefox.
- **Load or query performance.** Nothing was measured.

### Known to fail, so not tested

- **plumbline.** `bin/plumb run`, `bin/plumb bots push` and the five bots use `loopway bots`, which this PR removes. They stop at merge until they're rewritten as readers. `craftmill/site` also still describes the old product.
- **v2 itself.** The single inbox, `read`, `poll`, the 14-day purge and the hosted MCP aren't built, so they can't be verified here. `docs/v2.md` has that list.
- **The landing page copy.** It renders correctly, but it still says the project was put down and describes the old bots.
