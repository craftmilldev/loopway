# Verification for PR 504: state per `.loopway` project

This PR moves loopway's state (the discovery cursors in `state.json`, the threads) from `~/.loopway` into the project, as `.loopway/state/`, so two projects never see each other's threads. Everything below ran on 2026-11-10, on a Mac, on code from this branch, against `craftmilldev/loopway-sandbox`.

**Bottom line:** steps 1 to 5 of the issue all behave as written. Every write went to the sandbox (issues #5 and #6, both closed afterwards); no write was refused.

The new tests (`threads.test.ts`, "per-project state"): two project directories over a fake GitHub, where neither sees the other's threads or cursors; the state lives in `<project>/.loopway/state` with a `.gitignore` of `*`; an edited `.gitignore` is left alone, and `LOOPWAY_STATE` moves the directory.
