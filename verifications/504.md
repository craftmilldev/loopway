# Verification for PR 504: state per `.loopway` project

This PR moves loopway's state (the discovery cursors in `state.json`, the threads) out of the top of `~/.loopway` into `~/.loopway/state/<slug>/`, one folder per project, so two projects never see each other's threads. The slug is the full path of the project's `.loopway` folder with every character other than a letter or digit turned into `-`, the way Claude Code names `~/.claude/projects/` folders. Everything below ran on 2026-11-10, on a Mac, on code from this branch, against `craftmilldev/loopway-sandbox`.

**Bottom line:** steps 1 to 5 of the issue behave as written, with step 4 changed to match the review (nothing is written into the project but the bot files). Every write went to the sandbox (issues #7 and #8, both closed afterwards); no write was refused.
