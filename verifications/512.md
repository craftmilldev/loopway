## Live, in `craftmilldev/loopway-sandbox`

Setup: `scratch/.loopway/dev.md` with `repos: [craftmilldev/loopway-sandbox]`, `on: issue`, `model: sonnet`, prompt "Do what the issue asks, then comment with the result.", and no `allow`/`deny`.

**Step 2 needed a change.** I opened an issue asking for `curl -s https://example.com | head -3`. Another loopway running against the sandbox at the same time ran it for the same issue, so I probed with the built code directly (`claudeRunner` and `startMcp` from `dist/`, logging every permission request): with `--permission-mode auto`, the classifier let through `curl`, `curl -X POST -d @/etc/hosts`, `sudo -n true`, `git push`, `rm`, `Write` to `/tmp` and to `~`, `WebFetch` and `WebSearch`, and none of them reached the `permission` tool. A project rule does reach it: `scratch/.claude/settings.json` with `{"permissions":{"ask":["Bash(curl:*)"]}}` made Claude Code send the `curl` call to `mcp__loopway__permission` (the probe printed `PERMISSION Bash {"command":"curl -s https://example.com | head -3","description":"..."}`). All the runs below used that file. The tool, and the front matter `allow`/`deny` rules, are what decide once Claude Code does prompt.
