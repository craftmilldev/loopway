# Verification for PR 493: PostHog on the marketing page

Ran on 2026-11-10, on a Mac, with `packages/web/public/index.html` from this branch served on `http://localhost:4173`, loaded in Chrome for Testing driven by Playwright (the GitHub navigation was stubbed, so no real request to github.com).

**Bottom line:** one request carries `$pageview` on load and one carries `github_clicked` on the click, both to `a.craftmill.dev`, and both events are in PostHog. The page sets no cookies. Browsers block reading the proxy's response from localhost until the page's real origin is in the proxy's `ALLOWED_ORIGINS` (the events were still ingested).

## Requests to a.craftmill.dev

Only the script and two event POSTs, no flags, config, dead-click or web-vitals requests:

```

  GET  https://a.craftmill.dev/api/ingest/static/array.js            200
  POST https://a.craftmill.dev/api/ingest/e/    {"api_key":"phc_BPP9dYn...","batch":[{"event":"$pageview",...
CLICK (url after: https://github.com/craftmilldev/loopway)
  POST https://a.craftmill.dev/api/ingest/e/    {"api_key":"phc_BPP9dYn...","batch":[{"event":"github_clicked",...
cookies: []
```

The click request was sent before the page navigated (`sendBeacon`).

The browser console showed one CORS error for the page-load POST: `Access to fetch at 'https://a.craftmill.dev/api/ingest/e/' from origin 'http://localhost:4173' has been blocked by CORS policy`. The proxy lists only Craftmill origins, so the production origin has to be added to its `ALLOWED_ORIGINS`.
