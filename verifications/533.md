# Verification for PR 533: Pick up issues older than loopway when something happens to them

Ran on 2026-11-12, on a Mac, with the CLI built from this branch. #531 has no "How to test it" section, so there were no steps to follow; the live part below is smaller than a full run and says so.

**Bottom line:** the automated checks pass and the new tests cover the fix. Live, I only confirmed that GitHub's `issues?sort=updated&since=` returns what the new discovery relies on. I did **not** run the whole loop (an old issue is touched, loopway reports it new, a dev thread starts).

New tests: `poller.test.ts` checks that an old subject by you is reported new once it is touched, and only the waking update is reported (its older update is not); that old subjects by others are ignored; and that a known subject is not reported new again. `github.test.ts` checks that `discover` returns an old issue touched after `since`, and requests `sort=updated&direction=desc&since=<since>`.

## Live, in craftmilldev/loopway-sandbox

Read-only: the built `GitHubSource.discover` against the sandbox with `since=2026-11-11T02:37:00Z`. It returned 26 issues, newest activity first, for example `#42 created 2026-11-11T04:14:29Z updated 2026-11-11T04:19:36Z`. I did not see in that output an issue created before `since` and touched after it, because I only printed the first 8 lines. So this shows the request works and orders by activity, not the case that matters.
