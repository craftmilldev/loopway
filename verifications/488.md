## What I could not check

- **Timing against a live write.** The 2-minute and 30-second cadence is proven in tests with a fake clock, not on a clock.
- **Commit statuses on a real PR** (check runs are shown above); they are covered by the fake `fetch` tests only.
- **That the probe notices a change live.** The unchanged and changed paths are tested with fakes, and the real query is accepted, but I did not watch a quiet loop turn into a poll against the live API.
- **A real rate limit.** The 403/429 handling is tested with synthetic headers. I did not run GitHub out of requests.
- **The Vercel deploy.** `vercel.json` now serves `public/` with no install or build (a test asserts that), but I did not run `vercel build`, which needs a linked project. Check the first deploy after merge.
- **Deletion's effect on the live service.** Code only: the old Vercel deployment, its database and plumbline's `runner/reader.mjs` and loopway MCP are untouched and will stop working as agreed on #486.
