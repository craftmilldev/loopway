Claude Code, Codex or whichever you use. It reads loopway's docs, asks what the bot should do, creates the inbox and the bot in mcwhittemore, and hands you the webhook URL to add in that service.

Set up a loopway bot for me in my loopway org "mcwhittemore".

First read https://loopway.craftmill.dev/llms.txt: it explains loopway and its CLI.

1. If `loopway` isn't installed, install it (needs Node 22+). Run `loopway login`; it emails me a one-time code, so ask me for it.
2. Ask me what I want the bot to do and which service it should hear from. Then create the inbox and the bot with `--org mcwhittemore`, and tell me the webhook URL and secret to add in that service.
3. Check `loopway runners`. A runner already online for this org picks the new bot up by itself; if there is none, start one with `loopway bots run --org mcwhittemore` in the directory the bot should work in, and leave it running.
Your agent will ask for the one-time code; it goes to the address you logged in with.

By hand

Or run the CLI yourself

  1. loopway inbox create --org mcwhittemore Name it, pick the source (GitHub, Linear, Vercel, a schedule…) and keep the secret it prints. It is shown once.
  2. loopway bots create --org mcwhittemore Pick the harness, the model and the inbox, then write the prompt: what the bot does when a message arrives.
  3. Nothing to restart Your runner picks the new bot up on its next poll.
Every flag is in the CLI reference.

What makes a good first bot

Something small that reads one kind of message and writes one thing back: summarize a pull request when it opens, or file a Linear issue from a failed deploy. Bigger jobs come easily once you have seen one run.

Where it runs

In the directory your runner started in, with the credentials that machine already has. loopway never sees your code; it only passes the message along.
