The quick way

Send a test message

loopway posts a sample pull_request event to github, signed the way GitHub would sign it. The bot treats it like any other message, and the inbox marks it as a test.

About ten seconds to the first run.

The real thing

Add the webhook in GitHub

In the repo, under Settings, then Webhooks. Content type is JSON.

Payload URL
https://loopway.craftmill.dev/api/webhooks/inb_7f3a9c
Secret
Shown once when the inbox was made; your agent has it. Lost it? Set a new one with loopway inbox update github --secret and paste the same value in GitHub.
Events
Pull requests and pushes. Anything else answers 422 and GitHub shows it as a failed delivery.

What a run looks like

The runner opens a session with the bot's prompt and the message, in the repo it started in. The transcript stays on your machine; this page shows the thread, who holds it and what was delivered.

If nothing happens

Check the terminal the runner is in: it logs each message it picks up. A delivery GitHub marks as failed usually means the secret differs or the event type is not one the inbox takes.
