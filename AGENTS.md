# Agent instructions

- loopway 2.0 is local and light: plain TypeScript, JSON files under `~/.loopway/`, few dependencies. Don't add a server, a database or an abstraction a slice doesn't need. The plan is in [#486](https://github.com/craftmilldev/loopway/issues/486).
- Tests never touch the network: GitHub is faked (`packages/cli/test/fake.ts`, and a fake `fetch` in `github.test.ts`). Live runs belong in `verifications/<pr>.md`.
- Vercel skips the web build when nothing web depends on changed (`packages/web/scripts/should-build.mjs`, run as `ignoreCommand`). It follows `@loopway/*` dependencies from `packages/web/package.json`, plus the root files in `ROOT_INPUTS`. `packages/web` is one static page with no dependencies, so today that means `packages/web` and the root files. If web ever reads a file outside `packages/web` and the packages it depends on, add that path to `ROOT_INPUTS` in the same PR. A redeploy of the same commit is always skipped, so to apply an env var change set `FORCE_BUILD=1` on the project, redeploy, then remove it.
- Live verification runs (the "How to test it" steps in an issue, recorded in `verifications/<pr>.md`) write to the private repo `craftmilldev/loopway-sandbox`, and only there. It exists for this; don't ask which repo to use, and never write to any other repo while verifying. Put the PR number in the title of every issue and PR you open there (`[#494] reopen starts a new thread`), close them when the run is done, and delete any branches you pushed. Start every live run from `npm run init-scratch -- --reset` in your worktree, not a hand-made directory: it makes `scratch/` (git-ignored) with dev and review bots on the sandbox repo, and clears that project's state so you start with no threads. Run loopway from `scratch/` with the built CLI (`node <worktree>/packages/cli/dist/index.js`).
